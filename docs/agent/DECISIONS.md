- 2026-11-25 | P8.T3 refresh is PATH-based, not file-id-based. ROADMAP said "maps file ids to snapshot nodes", but the v1/v2 snapshot body stores names, sizes and flags only — no NTFS file ids — and adding ids would change the on-disk format for a feature a path delta already covers. So: the elevated helper resolves each journal entry to its CURRENT path with an UNCACHED `volume.path_resolver()` (a cache is explicitly unsafe across renames per the crate docs), stats the path, and sends one change per distinct path; `bytemap-core::refresh::apply_changes` matches those paths case-insensitively against the snapshot tree (last event per path wins; removal-then-create drops the old subtree).
